The OSSL container

source

OSSL

def OSSL(
    df:pandas.DataFrame, # OSSL data, one row per sample
):

OSSL (Open Soil Spectral Library) data container, indexed by sample ID

OSSL indexes its DataFrame by sample ID (id), using the id.layer_uuid_txt column. The OSSL documentation names this column as the key for joining OSSL tables. Every row has a distinct value.

OSSL passes any attribute it doesn’t define to its DataFrame, through fastcore’s GetAttr. So ossl.loc, ossl.columns and the other DataFrame attributes work directly on ossl. Indexing with a column name or a list of names returns those columns, as in pandas. Indexing with anything else, such as a boolean mask, returns a new OSSL with the selected samples.

The local ID id.layer_local_c is not unique. In OSSL v1.2, 82 local IDs appear in two source datasets. For example, 1002 identifies one sample in CAF.SSL and another in KSSL.SSL. Joining on the local ID pairs the spectra of one sample with the properties of the other. To see the local ID and its source dataset, select them with ossl[['id.layer_local_c', 'dataset.code_ascii_txt']].

Get cache path for OSSL data

The cache directory is ~/.soilspecdata by default:

get_cache_path()
Path('/Users/franckalbinet/.soilspecdata')

load_ossl downloads the whole OSSL v1.2 database as one gzipped CSV file. OSSL publishes it at two data levels:

  • L0 (the default, ossl_all_L0_v1.2.csv.gz) keeps the lab method of each source dataset. The same property can have one column per method, such as cec_usda.a723_cmolc.kg and cec_iso.11260_cmolc.kg.
  • L1 (ossl_all_L1_v1.2.csv.gz) converts properties measured with different methods to one target method. It has 24 fewer property columns than L0, for example no cec_iso.11260_cmolc.kg.

Both levels have the same spectra and ID columns. load_ossl caches the file under its own name, in the directory from get_cache_path. Each level or url therefore has its own cache file.

Columns

OSSL sorts the columns into VISNIR spectra (visnir_cols), MIR spectra (mir_cols) and all other columns (meta_cols). The other columns hold soil properties, site data and metadata:

ossl.visnir_cols[:2], ossl.mir_cols[:2], ossl.meta_cols[:2]
(['scan_visnir.350_ref', 'scan_visnir.352_ref'],
 ['scan_mir.600_abs', 'scan_mir.602_abs'],
 ['dataset.code_ascii_txt', 'id.layer_local_c'])

meta_cols has 133 columns in v1.2. Soil-lab column names follow the pattern <property>_<method>_<unit>. For example, cec_usda.a723_cmolc.kg is the cation exchange capacity (CEC), measured with USDA method A723, in cmolc/kg. To find the columns for one property, filter on its name:

[c for c in ossl.meta_cols if c.startswith('cec')]
['cec_iso.11260_cmolc.kg', 'cec_usda.a723_cmolc.kg']

The same property can have several methods. The methods come from USDA or ISO standards, aqua regia extraction (aquaregia) or Mehlich-3 extraction (mel3). The table below counts the soil-lab columns of each property by standard. It leaves out the ISO 8601 date columns and the ISO 3166 country column, which use ISO formats rather than lab methods:

lab = lab[~lab.method.isin(['iso.8601', 'iso.3166'])]

OSSL._extract_wavenumbers

def _extract_wavenumbers(
    cols:List[str], # Spectral column names
)->numpy.ndarray: # Wavenumbers in cm⁻¹

Wavenumbers of spectral columns, converting VISNIR wavelengths in nm to wavenumbers

MIR column names give the wavenumber in cm⁻¹, as in scan_mir.600_abs. VISNIR column names give the wavelength in nm, as in scan_visnir.350_ref. _extract_wavenumbers converts wavelengths to wavenumbers (10⁷/λ, rounded to the nearest integer), so every method of OSSL works in wavenumbers. The 350 nm VISNIR column becomes 28571 cm⁻¹:

ossl.mir_cols[0], ossl._extract_wavenumbers(ossl.mir_cols)[0], ossl.visnir_cols[0], ossl._extract_wavenumbers(ossl.visnir_cols)[0]
('scan_mir.600_abs', np.int64(600), 'scan_visnir.350_ref', np.int64(28571))

def _filter_wavenumbers(
    wavenumbers:numpy.ndarray, # Wavenumbers of `cols`
    cols:List[str], # Spectral column names
